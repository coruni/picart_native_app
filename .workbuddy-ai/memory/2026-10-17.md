## 回复框功能面板重构（同日）

**目标**：消除重复渲染、修复键盘避让与功能面板互相抢高度。

**根因诊断**（`components/comment/CommentComposerModal/CommentComposerModal.tsx`，原 1222 行）

1. **每帧两次 setState**：`animatedPanelHeight` 与 `reservedKeyboardHeight` 各由一条 `Animated.Value.addListener` 驱动，动画期间 60fps 全组件重渲染。
2. **5 套键盘监听打架**：RN `Keyboard.addListener(willShow/willHide)` + `KeyboardEvents(didShow/didHide)` + `KeyboardEvents(willShow/willHide)` + `useKeyboardState` + 单独的 didShow 订阅；每套都调 `scheduleSnapToIndex`，同一帧 snapToIndex 被调 4~5 次。
3. **三个 ref 互相试探**：`pendingPanelModeRef` / `pendingKeyboardOpenRef` / `shouldFocusKeyboardRef` 表达「键盘收完再开面板」，过渡期 `accessoryHeight` 会短暂归零导致 sheet 掉高再回来。
4. **面板按高度条件挂载**：`visiblePanelMode === "emoji" && panelHeight > 0`，收起动画一开始就卸载 EmojiPanel（内容瞬消），再打开重新拉一遍表情图。
5. **focus 重试 6 次**：`[0,32,96,180,320,520]`，每次触发 onFocus → 额外 6 次 snapToIndex。
6. **`RichComposerInput` 的 effect 依赖 `onReady`**：父组件每次重渲染都重建 onReady → effect 重跑 → `clearKeyboardTarget()` 清掉 BottomSheet 的键盘目标，表现为「键盘起来了 sheet 不跟」。
7. **Android adjustResize 压缩 window**：`useWindowDimensions().height` 变小 → `maxAccessoryHeight` 变小 → 键盘收起/面板展开途中面板被裁。

**重构方案**

- 引入 `DockMode = "none" | "keyboard" | "panel"` 单一状态机；键盘与面板**共用同一占位高度**（都取实测键盘高度），切换时 sheet 高度不变、只有内容互换。
- 删除两条逐帧动画链路（`animatedPanelHeight` / `reservedKeyboardHeight` / `animateReservedKeyboardHeight` / `keyboardHeightAnimatedValue` / `isClosingPanelRef` / `previousTargetRef`）。
- 键盘监听收敛为 `useKeyboardState` + 一个 `keyboardDidShow` 记录高度。
- `scheduleSnapToIndex` 补偿从 5 处收到 2 处（主动 + 90ms 兜底）。
- focus 重试 `[0,64,200]` + 一次 260ms 兜底，`onFocus` 触发即 `clearFocusRetryTimers()`。
- 面板改为「打开过一次后常驻挂载 + `display: none` 隐藏」，保住滚动位置、零重新挂载。
- `layoutWindowHeight` 用 state 记住「无键盘时的窗口高度」，键盘可见且 window 变小时忽略，只采纳旋转/分屏。
- 键盘态改用 `rawKeyboardHeight` 实测值，首次打开不再按默认 300 跳一次。
- `EmojiPanel` / `RichComposerInput` 加 `memo`；`RichComposerInput` 的 `onReady/onFocus/onBlur/onPress` 走 ref，切断 effect 依赖。
- `handleInputFocus` 里若 `dock === "panel"` 则强制关面板（键盘被外部唤起时让位）。

**chat 同步**（`app/chat/[id].tsx`）

- 面板同样改为常驻挂载 + `display` 切换，`setPanelMounted(true)` 放在事件内（不放 effect，避免 `react-hooks/set-state-in-effect`）。
- `EmojiPanel` 的 memo 对 chat 同样生效（props 已是 useMemo/useCallback）。

**结果**：`CommentComposerModal.tsx` 净减约 400 行（637 行改动，226+ / 465-）；该目录 ESLint 零告警；`tsc` 无新增错误。chat 仅 9 行改动，存量 8 个 React Compiler 错误未变。

**踩坑**：`EmojiPanel.tsx` / `RichComposerInput.tsx` / `composerConstants.ts` 是 **CRLF** 行尾，`CommentComposerModal.tsx` 是 LF；批量替换必须按文件判断行尾，否则 assert 全挂。

## 键盘时序与面板高度三修（同日续）

用户反馈三条，全部定位到「高度变化的时序」这一族问题。

### 1. 虚拟键盘关闭后 sheet 要等一会儿才缩下去

**根因**：`useKeyboardState` 内部只监听 `["keyboardWillShow", "keyboardDidHide"]`
（见 `node_modules/react-native-keyboard-controller/src/hooks/useKeyboardState/index.ts:8`）。
显示走 willShow（动画开始就有高度），收起走 didHide（动画结束才归零）。
于是 sheet 在整段 ~250ms 收起动画里保持原高度，动画结束再瞬间掉下来。

**修法**：自己订阅 `KeyboardEvents.addListener("keyboardWillHide")`，在动画开始就
`setDock("none")`，并用 `event.duration` 作为 `snapToIndex(0, { duration })` 的时长
（gorhom 的 `animate.ts` 见到 `duration` 会从 spring 切成 timing），两者同步收。

**踩坑**：`sheetHeight` 变化会触发定位 effect 里的 `scheduleSnapToIndex()`（无时长，
走 spring），把 willHide 设好的时长覆盖掉。改为用 `snapDurationRef` 传递时长，
effect 里的调用也能读到，用完即清。`onDismiss` 里也要清。

原来的 `keyboardVisible` effect 保留为兜底（Android 11 以下没有 willHide）。

### 2. 选图后不自动弹起键盘

**根因**：`handleImagePress` 只处理了「sheet 被系统关掉要重新 present」，
从来没有还焦点。相册是原生页面，打开必然失焦收键盘，返回后停在
「既没键盘也没面板」的中间态。

**修法**：进相册前记 `shouldRestoreKeyboard = dock === "keyboard" || isInputFocusedRef.current`；
返回后 `settleAfterPicker()` 统一收尾（重新 present + `restoreKeyboardAfterPicker(delay)`）。
`settleAfterPicker` 用 `settled` 标志保证幂等，`finally` 里再兜一次异常路径。
delay 取 `PICKER_RESTORE_FOCUS_DELAY_MS = 240`，重新 present 时 +120。

### 3. 聊天页开面板时聊天记录被上顶 + 多余内容高度

**根因**：面板是行内渲染在输入行下方的，撑高 `KeyboardStickyView` 的同时
已经让 `chatArea`（flex:1）等量收缩 —— 列表视口本身就矮了一截。
而 `handlePanelLayout` 又把 `BASE_BOTTOM_HEIGHT + panelHeight` 上报给
`extraContentPadding`，等于同一个高度被预留两次：
内容被上顶两次，最后一条消息和输入框之间多出一块 panelHeight 的空白。

**修法**：`handlePanelLayout` 只保留 `freeze.value = false`，不再上报高度。

**自洽性验算**（结论：in-flow 布局下 extraContentPadding 应恒为 0）：
- 键盘关：bar 在流内，chatArea 底 = bar 顶，无需额外 inset。
- 键盘开：`KeyboardStickyView` 只做 translateY 不改布局，bar 上移 K 遮住列表底部 72px；
  同时 `KeyboardChatScrollView` 抬升 K，最后一条消息正好落在 bar 顶上。两者抵消。
- 面板开：bar 在流内长高 P，chatArea 等量收缩 P，消息上移 P 后紧贴 bar。不需要 inset。
