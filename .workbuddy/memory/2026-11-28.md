# 2026-11-28

## openapi 第三版对接（后端补齐字段/参数后重新生成）

- 新 spec 修了不少东西：`config`（`DtoUserConfigDto` 全量通知/隐私/水印）、
  `DtoUpdateUserConfigRequest` 的开关字段、`DtoRegisterRequest` 的 `invite_code`/`verification_code`、
  `DtoUpdateContactRequest`、`/article` 的 `sort`、`/search` 的 `category_id`/`sort_by`、
  `/search/tags`、`/search/users`、`/article/browse/history` 的 `order`、`/message` 的 `type`、
  私聊消息 `cursor`/`limit`、`/comment/{id}` 回复分页。
- 因此把上一版所有「拉全量 + 本地过滤 / 只拉第一页」的降级都换回服务端参数；
  `types/compat.ts` 从 7 个类型缩到 5 个，`api/compat.ts` 从 4 个函数缩到 3 个。
- **spec 现在有 25 个 operationId 重复**（同一接口同时留了 camelCase 和 snake_case 两条 path），
  `openapi-generator` 直接报错退出。`package.json` 的 `openapi` 脚本先加
  `--skip-validate-spec` 绕过；后端删掉多余 path 后要去掉这个 flag（交接文档里列了完整 25 条）。
- 仍缺（已写进 `docs/api-compat-handover.md`）：评论 `article`/`parent`、资料
  `equipped_decorations`/`is_followed`、`DtoUserDto.is_followed`、活动内嵌 `article`/`decoration`、
  装饰列表的归属/装备状态、浏览历史 `id`、评论 `sort_by`、`read-all` 的 `type`、socket 事件定义。
- 顺手修了装饰页的老问题：`DecorationCardItem.id` 改 string，DTO → 卡片模型改成真映射
  （之前是 `as unknown as` 硬转，`image_url` 对不上 `imageUrl`，图片全空）。
- 踩坑：`page`/`limit` 在不同接口有的是 number 有的是 string，传参前统一 `String()`，
  别按签名猜。

## 更正（同日，用户确认）

- **浏览历史不需要额外主键**：一条记录对应一篇文章（看多次记在 `view_count`），
  `article_id` 就是唯一键，单条删除 `DELETE /article/browse/{article_id}`、批量删除
  `POST /article/browse/batch-delete` 都按它。已删掉 `types/compat.ts` 的 `BrowseHistoryView`，
  `HistoryTab` 的 `historyKey` 直接用 `article_id`，交接文档里「缺 id」那一条也删了。

## 登录页加短信登录（同日）

- `LoginPanel` 顶部加了「密码登录 / 短信登录」分段切换：轨道 `theme.muted`，
  选中项浮回 `theme.card`（`styles.modeSwitch` / `modeItem`），替换掉原来那句
  「请使用邮箱登录」标题（该文案和短信模式矛盾）。
- 两套表单共用一个 `useForm`，`validationRules` 按 mode 现算 —— `useForm` 的
  `validateAll` 只校验传入 rules 里的 key，切模式不会残留另一套的报错。
- 手机号 / 验证码**只收数字**：`onChangeText` 里 `replace(/\D/g,"")` + 截断
  （手机 11 位、验证码 6 位），另加 `keyboardType="number-pad"` + `maxLength` 双保险；
  粘贴 `+86` 开头会去掉国家码（`normalizePhone`）。
- 发码倒计时逻辑照搬 `RegisterPanel`（60s，`timerRef` 卸载时清）。
- `POST /auth/sms/login`、`/auth/sms/send` 的 spec **同样没写 requestBody**，
  走 `api/compat.ts` 的 `smsLogin` / `sendSmsCode` 手动补 body（compat 现在 5 个函数）。
- 新增文案键（zh/en）：`auth.passwordLogin`、`auth.smsLogin`、`auth.phoneLabel`、
  `auth.phoneRequired`、`auth.phoneInvalid`、`auth.codeInvalid`。
- **入口暂时隐藏**：`app/auth/index.tsx` 的 `SMS_LOGIN_ENABLED = false` 挡住分段切换，
  关掉时登录面板恢复原来那句「请使用邮箱登录」标题；代码整条链路留着，
  后端短信通道开通后把这个常量翻成 `true` 就能放出来。

## 后端 message 改成 key + 中英语言包（同日）

- 后端从 2026-11-27 起响应里的 `message` **直接回 i18n key**（如 `auth.need_login`），
  翻译由前端做。权威表是 `27-i18n文案对照表.md`（337 key × 5 语言），
  **前端只保留 en / zh-CN**，繁中 / 日 / 韩不要（用户明确要求）。
- 生成链：表存 `docs/i18n-source.md` → `python scripts/gen-api-i18n.py`
  → `locales/api/en.json` + `locales/api/zh.json`（按 `.` 拆成嵌套对象）。
  产物勿手改，后端改文案就重跑脚本。
- 挂载方式：`locales/i18n.ts` 里 `{ ...en, api: apiEn }`，后端 key 全在 `api.*` 下，
  **不和界面自己的 `auth.login` / `auth.smsLogin` 撞名**（那边是 `api.auth.login_success`）。
- 查表入口 `lib/apiMessage.ts` 的 `translateApiMessage(raw, values?)`：
  查不到 key 就原样返回（兼容老接口回纯中文），占位符按顺序填、
  没值就抹掉并清掉悬空冒号（「分类名已存在」而不是「分类名已存在：%s」）。
- 接上的 7 处：登录/注册/找回密码、改密码、实名认证、举报、发布（`getServerErrorMessage`
  内部已翻译）。之前这些地方是直接把服务端原文弹给用户。
- **坑**：`getServerErrorMessage` 返回值现在可能是中文，`isTooLargeRejection`
  靠 `/too large|过大/` 判 413 的逻辑仍然有效，但别再往里加英文-only 的正则。
- 交接文档加了「六、i18n」章节，向后端提两件事：① 38 个带 `%s/%d` 的 key 只给 key
  不给值，建议加 `message_args`；② 337 条打编译包，旧版本遇到新 key 会显示裸 key，
  建议加 `GET /i18n/{lang}` 覆盖 + 本地包兜底。
