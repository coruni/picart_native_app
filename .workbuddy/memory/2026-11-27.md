# 2026-11-27

## openapi 第二版对接（snake_case / ID string / data.list）

- 后端把 `openapi.json` 换成 snake_case 全域版本：字段、请求体、socket 都改蛇形；ID 由
  number 变 string（UUID）；列表包装从 `data.data.list` 改成 `data.list`。前端全量适配完成，
  `npx tsc --noEmit` 与 eslint 均 0 error。
- 三类系统性改动的连带影响：`Number(id)` 比较 → 直接比 string；`Set<number>` → `Set<string>`；
  `keyExtractor` 统一 `String(item.id ?? "")`；乐观消息临时 ID 由负数改成 `local-` 前缀
  （`app/chat/[id].tsx` 的 `LOCAL_ID_PREFIX`）。
- 后端缺字段一律「占位不删功能」：
  - `types/compat.ts`：`AuthUserView` / `UserProfileView`(`config`、`equipped_decorations`、
    `is_followed`) / `UserView`、`CommentView`(`article`、`parent`)、`ActivityView`
    (`article`、`decoration`)、`BrowseHistoryView`(`id`、`created_at`、`updated_at`)。
  - `api/compat.ts`：4 个 spec 没写 requestBody 的接口（发验证码 / 重置密码 / 改密码 /
    改联系方式）手动把 body 补回去。
- 后端缺查询参数一律降级：排序 / 分类 / type 过滤 / cursor 用「拉全量 + 本地过滤」或
  「只拉第一页 + `void xxx`」占位，不删 UI。
- 交接文档：`docs/api-compat-handover.md`（按 A~E 分组列缺什么、前端怎么兜、补齐后怎么删）。
- 踩坑：`tsconfig.json` 的 `include` 是 `**/*.ts` + `**/*.tsx`，但根目录新建的 `.tsx` 探针文件
  不会被 tsc 收录（`.ts` 才会）。写临时类型探针要用 `.ts`。
- 踩坑：`Omit<交叉类型, "某字段">` 会让交叉类型里「另一侧」的属性推断成 `{}`，
  `article?.images?.[0]` 直接报 TS7053。改用「交叉类型 & { 字段?: 更精确类型 }」，
  且占位对象别手写形状，直接 `Partial<DtoArticleDto>` 更准。
