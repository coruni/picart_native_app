# 2026-10-20

## ArticleDetail 图片类型「相册下方多一段空白」

**现象**：图片（图集）文章的相册区底下多出一截空白，导致「相册 → 文章标题」的间距
比 mixed（封面 16:9）/ video（播放器 16:9）两个类型大。

**根因**：`ArticleSwiper` 的容器高度写死了兜底值，和实际渲染的图不是同一个比例，
而图是 `objectFit: contain` —— 比例对不上就在上下各留一半空白：

```ts
const firstImageHeight =
  typeof images[0] === "string"
    ? 380                                            // 老数据：写死 380
    : (images[0].height / images[0].width) * width;  // 对象数据：原图尺寸
```
对象数据里 `width/height` 是**原图**的，真正渲染的是 `getImageUrl(item,"large")`
的缩略图，比例可能被裁过；外加 `minHeight: 180` 会把宽幅图撑高。

**修法**（`components/article/ArticleSwiper.tsx`）：
- 新增 `useImageRatio(url, fallback)`：用 `Image.getSize` 量**实际展示的那张图**的比例，
  模块级 `imageRatioCache` 按 URL 缓存，只量一次；对象数据先用 `width/height` 兜底首帧。
- 高度改成 `clamp(ratio * 屏宽, 100, 480)`，容器上不再挂 `minHeight`/`maxHeight`，
  比例和容器一致 → contain 不留竖直空白。
- 下限从 180 降到 100：下限只要高于图片比例就会重新产生留白，横幅图宁可矮一点。

**注意**：相册高度仍按「首图」定，滑动到其它比例的图时容器不跳变（相册惯例）；
如果要求每页自适应，就把 ratio 换成 `images[currentPage]` 的。
`eslint` 的 `react-hooks/set-state-in-effect` 不允许在 effect 里同步 setState，
所以 ratio 用「渲染时读缓存 + 异步量到后 setState」的派生写法，不要写回 state。
