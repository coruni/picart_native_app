## 视频编辑器：重写预览播放（expo-video → react-native-video）

用户反馈「拉动闪烁 + 无法播放」「点一下自动暂停」「播一下停一下」，要求不行就重写。

**定位过程（真机 + 临时调试文本，logcat 本环境读不到）**
- 点击是生效的（按次计数 p1），JS 侧 `pauseVideo` 调用为 0，`status` 始终 readyToPlay。
- 完全静默（无 VideoView、无重试、无 setState）时：play 后 0.1 秒出现一次
  playing=false，随后 3.4 秒内不再变化 → 原生层一次性 pause。
- `dumpsys audio` 焦点栈为空；`duckOthers` / `mixWithOthers`+muted 结果相同；
  HOME 再回前台也一样。→ expo-video 的 play 在本机不可用。
- 之前的「播放意图自愈」只是把被按掉的播放一次次救回来，表现成每 400ms 卡一下。

**重写方案**
- 播放：`react-native-video` 的 `<Video paused viewType={ViewType.TEXTURE}>`，
  单一 `paused` 状态驱动；片尾用 `ended` + 手动 seek(0) 重播。
- 抽帧：保留 expo-video 的 `generateThumbnailsAsync`，但改成
  「先抽完 10 帧 → 再挂 RNV 播放器」；抽帧期间挂一个与预览区等大的隐藏 VideoView，
  抽完卸载（否则吃掉点击）。抽帧阶段用首帧 Image 占位。
- 抽帧 / 抓帧全部包 `withTimeout`，抓帧超时回退到最近一帧。
- 圆角：RNV 的 TextureView 不吃父层裁剪，用四角逆向圆角遮罩（卡片底色）实现。

**踩过的坑**
- 抽帧 effect 依赖里放 `status` → 状态跳变触发 cleanup，抽到 2 帧就断，重跑又被
  uri guard 挡住。
- 隐藏抽帧视图缩成 1x1 时，`generateThumbnailsAsync` 第 2 帧就挂死。
- 两个播放器同时开：抽帧第 3 帧起永久挂死。
- 点击层必须放在 stage 最后（最上层），否则被原生视频视图挡掉。

**验证**（设备 10AG9L12CN003NT，视频 00:06 / 5.3MB）
- 播放连续推进 0→6.8s；进度条跟随；片尾显示重播并可从 0 再播。
- 拖动进度条松手定位到 00:02，画面同步；「用当前画面」自动打勾。
- 10 张封面帧全部抽出；「完成」后面板关闭、卡片封面已更新。
- `npx eslint` 与 `npx tsc --noEmit` 通过（tsc 仅剩 api/generated/api.ts 的历史报错）。

## 修复视频预览区圆角（SVG 遮罩）

现象：预览区四个角是完全的直角（真机截图确认）。

根因：上一版用四个 `12×12` + 单角 `borderRadius` 的 View 做遮罩，但它们挂在
`styles.stage` 内部，而 `stage` 自己有 `overflow:hidden` + `borderRadius`。
遮罩要盖的位置恰好是 stage 圆角**之外**，于是被 stage 的裁剪整个裁掉 —— 等于没画。

另外一个更根本的问题：`borderRadius` 只能「裁掉圆角的方形」，留不出「角落那块弧形三角」，
所以单靠圆角 View 其实也拼不出正确形状。

修法：
- 新增 `stageWrap`（16:9、不裁剪）包住 `stage`；遮罩放在 wrap 里、stage 之后。
- 用 `react-native-svg` 画一条 `fillRule="evenodd"` 的 path：
  「外矩形 + 内圆角矩形」只填差集，正好是四个角的弧形三角，随实际尺寸由 `onLayout` 生成
  （`buildCornerMaskPath`）。颜色取 `theme.card`，浅/深主题都对。
- 删掉旧的 4 个 corner 样式；`stageVideo` 上的 `borderRadius` 一并去掉（对 TextureView 无效，留着误导）。

验证：真机四角均可见圆弧；播放 00:02 推进时圆角保持；暂停、点击层命中都正常。
`npx eslint` / `npx tsc --noEmit` 通过（tsc 仅剩 api/generated/api.ts 历史报错）。

## 富文本字体颜色 / 背景色「选了不生效」

真因只在 Android 原生：`react-native-enriched-html` 的
`android/.../textinput/styles/InlineStyles.kt` 里 `parseCssColor` 用的是
`Color.parseColor(raw)`，它只认 `#rgb` / `#aarrggbb`，而
`constants/editorTextStyles.ts` 的整块色板取值全是 `rgb(230, 230, 230)` /
`rgba(0, 0, 0, 0.85)` 这种函数写法 → 每次都抛 `IllegalArgumentException`
→ 返回 null → 上游把 null 当成「清除」→ 选任何颜色等于把颜色抹掉。

修法（写进 patch）：自己解 CSS 颜色，支持 `rgb()/rgba()`（含 `%` 通道、
alpha 0~1 或百分比）、`#rgb/#rgba/#rrggbb/#rrggbbaa`（alpha 在最后两位，
不能直接交给 `Color.parseColor`，那货认的是 `#aarrggbb`）、颜色名兜底。
补丁已用 `npx patch-package react-native-enriched-html --exclude 'android/build'`
重新生成（2019 行），`git apply --check --reverse` 通过。

iOS 侧 `CssStyleUtils colorFromCss:` 本来就支持 rgb/rgba，未改。
`android/gradlew :react-native-enriched-html:compileDebugKotlin` 编译通过
（约 3.5 分钟，可用于单独验证原生改动，不必整包 run:android）。

## 颜色面板「一打开就自己关掉」

工具栏的挂载条件是父级那句
`editorEngaged && (keyboardShown || toolbarOverlayOpen)`
（`app/publish/index.tsx` 1142 行）。表情面板 / 输入 sheet 都会通过
`onOverlayChange` 把「我开着」报给父级，**功能面板（panel）从来没报过**。
于是只要面板开着的时候键盘收起来，父级就不再挂载工具栏，面板 state 跟着一起没了
—— 表现出来就是「点开颜色选择，面板闪一下就没了」。
色板里还有个 ScrollView，`keyboardShouldPersistTaps` 默认 `never`，
点色块的第一次点击也被用来收键盘，正好触发上面那条链路，色块还收不到 onPress。

修法（`components/publish/ArticleRichTextToolbar.tsx`）：
- overlay effect 的条件加 `panel !== null`：`emojiOpen || sheetOpen || panel !== null`。
  面板关掉会自动置回 false，父级 300ms 缓冲后释放挂载。
- 色板 ScrollView 加 `keyboardShouldPersistTaps="handled"`。

一般规律：**工具栏上任何「点开后会一直待着」的浮层，都必须计入
`onOverlayChange`**，否则键盘一收就跟着被卸载。

## 色板 ↔ 键盘互斥、键盘唤不回来（真机反馈）

三条一起改：
1. 面板上下内边距：`styles.panel` 的 `paddingVertical: 8` 对色板不适用，
   拆出 `palettePanel`（只有 `paddingHorizontal: 12` + 上边框），色板贴边铺满。
   容器高度取 `paletteHeight = max(panelHeight, 180)`，`panelHeight` 本身就是
   「键盘高度 - 工具栏行高」，所以面板正好顶替键盘的位置、工具栏不会上下跳，
   ScrollView 改 `flex: 1`。
2. 打开色板 `KeyboardController.dismiss({keepFocus:true})`，选完色 / 再点按钮 /
   切到别的面板都要把键盘还回来；色板开着时键盘自己弹回来（用户点了正文）
   就自动收面板，保证两者不叠加。
3. **键盘唤不回来的真因（iOS）**：`dismiss({keepFocus:true})` 在
   `react-native-keyboard-controller` 的 Swift 实现里是把输入框的 `inputView`
   换成一个空 `UIView` 并 `reloadInputViews()`，输入框仍是 first responder；
   `editor.focus()` → `reactFocus` 对已 firstResponder 的视图什么都不做，
   所以键盘永远起不来。必须用 `KeyboardController.setFocusTo("current")`：
   `ViewHierarchyNavigator.setFocusTo` 会置 `inputView = nil` + reload + focus。
   Android 上它对应 `FocusedInputHolder.focus()`，配合
   `EnrichedTextInputView.requestFocusProgrammatically()` 的
   `showSoftInput` 也能弹回键盘。
   统一抽成 `resumeKeyboard()`（还把光标放回原选区末尾），表情面板
   `closeEmojiPanel` 也改用它 —— 以前那里同样只 `focus()`，iOS 上键盘不会回来。

## 内联帖子（Inline Article）渲染

网页端用 `InlineArticleListBlot`（`picart_next/src/components/editor/blots/InlineArticleListBlot.ts`）
把内联帖子渲染成卡片块 `<div class="ql-inline-article-list" data-articles='[...]'>`，
样式在 `inline-article.css`（封面 80px/4:3、标题 14/500、作者 12、浏览数 12、`--color-muted` 底）。

移动端 **编辑器（react-native-enriched-html）存不下这种块**：它的
`EnrichedParser.fromHtml` 把 HTML 转 span，`data-articles` 这类自定义属性会被丢掉，
回读会把卡片块拍平。所以正文里只能放普通链接，元数据必须存在 React 侧。

做法（`lib/inlineArticle.ts` 新增）：
- 选择器确认时 `handleArticleConfirm` 仍按光标 `setLink` 插 `📄 标题` 链接（保位置、保可靠），
  同时把帖子元数据写进 `inlinePostsRef`（publish 页持有，传给 toolbar 的 prop）。
- 发布时 `upgradeInlinePosts(editorHtml, map)` 把带 `📄` 前缀且指向 `/article/<id>` 的链接
  升级成 `ql-inline-article-list` 卡片块（和网页端同结构，含 data-articles 供网页端再编辑）。
  外链无 `📄` 前缀，原样保留。
- 阅读端 WebView（`ArticleHtmlWebView.buildStyleBlock`）补了 `inline-article.css` 同款卡片样式，
  token 换成主题色（mutedBg=theme.muted、mutedFg=theme.mutedForeground、border、fg、primary）。
  注意 `ArticleHtmlWebView.tsx` 有个**既有** eslint 报错（renderBody 渲染期读 ref，与本次无关）。
- `RenderHtml`（react-native-render-html）也加了同名 classStyles 兜底，但 cover 图会被当成整宽图，
  好在信息流预览走纯文本，实际不会渲染到。

## 内联帖子选择面板：列表过长顶掉确认按钮

`components/publish/InlinePostSheet.tsx`：双列布局（columns/column）+ ScrollView 列表，
列表很长时确认按钮被顶出可视区。根因是 RN flex 默认 `minHeight:auto` 不收缩，
`ScrollView`/`View` 撑到内容高度、挤掉底部按钮。

修法：给 `root` / `columns` / `column` / `list` 都加 `minHeight: 0`，
让长列表在面板高度内自行滚动，确认按钮（marginTop:auto + 高 44）常驻底部。
已提交 `463a09f`，`npx eslint` + `npx tsc --noEmit`（排除 api/generated）通过。

后续（这次真机复测）：只改 flex 还不够，两个问题各自有独立的根因。

1. **确认按钮仍然在屏外**：`keyboardBehavior="interactive"` + `android_keyboardInputMode="adjustResize"`
   在库里有专门分支 —— Android 让位逻辑直接 `return`，只等 window 缩小；而面板是从工具栏打开的，
   键盘早就弹起，gorhom 的键盘 reaction 收不到那次 SHOWN，`heightWithinContainer` 恒为 0。
   同时 `snapPoints=["62%"]` 的百分比是按模态容器的 layout 高度的，键盘弹出时那高度已经缩过，
   双重压缩。改成和 `InputSheet` 同一套：`useKeyboardState()` 拿全局键盘高度做 `bottomInset`，
   `keyboardBehavior="extend"` 让库别插手，`snapPoints` 换成固定像素
   `max(windowHeight * 0.62, 420)`。
2. **两列都滚不动**：`BottomSheetScrollView` 靠 `useScrollableSetter` 注册「当前滚动容器」，
   同一个 sheet 里挂两个，后挂的会把前一个顶掉（`previousScrollableRef` 只回退一次），
   内容拖拽手势又挂在整块面板上，于是纵向手势全被面板吃掉。面板单档位、不需要内容区下拉关闭，
   直接 `enableContentPanningGesture={false}`，手势交还各自的 ScrollView。

一般规律：**同一个 bottom sheet 里放多个 `BottomSheetScrollView` 时，必须关掉内容拖拽手势**，
否则只有最后一个能滚。
