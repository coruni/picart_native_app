## Profile hero 封面点击区修复（app/(tabs)/profile.tsx）

问题：封面图的点击命中区和视觉区域不一致。

根因两条：
1. `heroImageLayer` 高度写死 `HERO_CANVAS_HEIGHT`，内部 `heroCoverPressable` 靠 `bottom: 0` 撑满。下拉刷新时图片按 `pullDownHeight` 长高，但命中区高度不变 → 多出来的部分点不到。
2. `hero` 是 `zIndex: 0`，`scrollShell` 是 `zIndex: 2` 且 top = `heroMinHeight`。封面可见区 `[0, 188]` 里只有顶部 `[0, heroMinHeight]` 那条能命中，中间那段（视觉上是封面）落在 ScrollView 的透明占位上，点了没反应。

修复：
- 新增 `AnimatedPressable = Animated.createAnimatedComponent(Pressable)`，命中区高度绑 `heroContainerHeight`（去掉 `bottom: 0`），下拉时长高会跟随。
- `heroImageLayer` 改为 `Animated.View` 且高度绑 `heroContainerHeight`，让 blur / gradient 层跟着走，子视图不越界。
- 滚动区顶部那块透明占位 `Animated.View` 换成同高 `Pressable`（放在 ScrollView 内部，因此不会抢走纵向滚动手势），补上 `[heroMinHeight, 188]` 的命中。
- 抽出 `handleOpenBackgroundCropper` 复用；hero 层保留无障碍标签，占位层用 `accessibilityElementsHidden` 避免重复播报。
- 清理死代码：`heroRef`、`heroImageLayerRef`、样式 `heroImageLayerPressable` / `heroCoverImage`。
- 新增 i18n key `profilePage.changeBackground`（zh 更换封面 / en Change cover）。

验证：`tsc --noEmit` 该文件无错；`eslint` 与改动前持平（29 errors 均为既有 tabViewPositionRef 等 ref-during-render 报错）。真机交互未跑，待 `npm run android` 手验。

注意：项目无 prettier 配置且全库是 4 空格缩进，直接用 `npx prettier` 会按 2 空格重排整份文件，污染 diff。格式化需谨慎。

## articleDetail reaction chips 改为请求期扫光（components/article/ReactionsStats.tsx）

去掉了点击的 `withSpring` 缩放弹跳（scale shared value + onPressIn/onPressOut 全部删除），底色 `interpolateColor` 过渡保留。

新交互：点按后只有被点的那颗 chip 连续扫光，接口返回（成功/失败）后再淡出关闭。
- 光带：`expo-linear-gradient` 绝对定位层（`styles.shimmer`，left/top/bottom 0），宽度 = chip 宽度 × 0.5（最小 24），`skewX: -20deg`，`translateX` 从 `-bandWidth` 到 `chipWidth`，`withRepeat(withTiming(900ms, Easing.linear), -1)`。
- 配色：亮色 `rgba(102,128,255,0→0.22→0)`（primary 蓝，浅底可见）；暗色 `rgba(255,255,255,0→0.16→0)`。
- 启停：`pending` 由父组件 `pendingReaction` 状态驱动（handler 里 `setPendingReaction(emoji)`，`finally` 清空）；关闭时先 `withTiming(0, 180ms)` 淡出再 `cancelAnimation` + 复位。
- 防闪烁：`SHIMMER_MIN_VISIBLE = 420ms` 最小可见时长，接口过快时用剩余时间延迟淡出，避免一闪而过。
- `loading` 仍全局禁用所有 chip，但只有 pending 的那颗动效。

验证：`tsc --noEmit` 该文件 0 错误，`eslint` 该文件 0 报错。真机未跑。

## CommentTab（个人页「评论」tab）内容交互补全

补齐 `components/profile/CommentCard.tsx` 里原有的空壳 `Pressable`：

- 整卡点击 → 跳 `/comment/[id]`（参数 id / articleId / articleAuthorId / comment JSON），与 `CommentReplyList` 的既有跳转约定一致。
- 引用文章块 → 跳文章页（原有逻辑，补 `event.stopPropagation()` 防止冒泡到卡片）。
- 被回复评论小字块 → 跳父评论详情（父对象无 `floor`，因此 `app/comment/[id].tsx` 的 Stack 标题改为 `floor != null ? 楼层 : commentCard.detailTitle`）。
- 点赞：乐观更新 + 失败回滚，`api.commentControllerLike`，图标 `fill` 高亮，文案 `likes > 0 ? 点赞数 : 点赞`。
- 更多按钮 → 新增 `components/feedback/CommentActionSheet.tsx`（guarded by 单例，放 tab 层不在每张卡挂 sheet）：复制 / 举报 / 删除。删除只在本人评论出现（`comment.author.id === currentUserId`），走 `useConfirm` + `commentControllerRemove`，成功后 `onDeleted(id)` 从列表移除；举报走 `useReport` + `reportControllerCreate(type: COMMENT, reportedCommentId)`。

关键实现细节（踩过的坑）：

- 点赞状态不放卡片本地 state：卡片内 `useEffect` 同步 props 会被 `react-hooks/set-state-in-effect` 拦；改为状态由 `CommentsTab` 的 `data` 承载，卡片纯受控，`handleLike` 在 tab 层做 map 替换 + 回滚。
- sheet 的菜单项不能写成 `[...].filter()` 或 `items.push({onPress: handler})`——handler 闭包读 `sheetRef`，React Compiler 规则 `react-hooks/refs` 会报 "Cannot access refs during render"。改为模块级 `SheetActionRow` 组件，把 handler 走 props 传入。
- `useCallback` deps 写 `comment?.id` 会触发 `react-hooks/preserve-manual-memoization`（推断依赖是 `comment`），要写成 `comment`。
- i18n 新增 `commentCard.*`（copy/copySuccess/delete/deleteTitle/deleteMessage/deleteSuccess/deleteFailed/reportSuccess/detailTitle），zh + en 同步。

验证：`tsc --noEmit` 与 `eslint` 对三个改动文件均 0 报错。现存全库报错与本改动无关：`api/generated/api.ts` 的 `Null` 未定义、`app/user/[id].tsx` 给 5 个 tab 传了未声明的 `refreshing`/`onRefresh`（页面级 PullToRefresh 已经接管刷新，这些 props 是死参）。
