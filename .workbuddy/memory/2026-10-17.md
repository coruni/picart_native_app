# 2026-10-17

## Profile hero 封面点击区修复（app/(tabs)/profile.tsx）

问题：封面图的点击命中区和视觉区域不一致。

根因两条：
1. `heroImageLayer` 高度写死 `HERO_CANVAS_HEIGHT`，内部 `heroCoverPressable` 靠 `bottom: 0` 撑满。下拉刷新时图片按 `pullDownHeight` 长高，但命中区高度不变 → 多出来的部分点不到。
2. `hero` 是 `zIndex: 0`，`scrollShell` 是 `zIndex: 2` 且 top = `heroMinHeight`。封面可见区 `[0, 188]` 里只有顶部 `[0, heroMinHeight]` 那条能命中，中间那段（视觉上是封面）落在 ScrollView 的透明占位上，点了没反应。

修复：
- 新增 `AnimatedPressable = Animated.createAnimatedComponent(Pressable)`，命中区高度绑 `heroContainerHeight`（去掉 `bottom: 0`），下拉时长高会跟随。
- `heroImageLayer` 改为 `Animated.View` 且高度绑 `heroContainerHeight`，让 blur / gradient 层跟着走，子视图不越界。
- 滚动区顶部那块透明占位 `Animated.View` 换成同高 `Pressable`（放在 ScrollView 内部，因此不会抢走纵向滚动手势），补上 `[heroMinHeight, 188]` 的命中。
- 抽出 `handleOpenBackgroundCropper` 复用；hero 层保留无障碍标签，占位层用 `accessibilityElementsHidden` 避免重复播报。
- 清理死代码：`heroRef`、`heroImageLayerRef`、样式 `heroImageLayerPressable` / `heroCoverImage`。
- 新增 i18n key `profilePage.changeBackground`（zh 更换封面 / en Change cover）。

验证：`tsc --noEmit` 该文件无错；`eslint` 与改动前持平（29 errors 均为既有 tabViewPositionRef 等 ref-during-render 报错）。真机交互未跑，待 `npm run android` 手验。

注意：项目无 prettier 配置且全库是 4 空格缩进，直接用 `npx prettier` 会按 2 空格重排整份文件，污染 diff。格式化需谨慎。
