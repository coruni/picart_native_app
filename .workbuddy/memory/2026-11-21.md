# 2026-11-21

## 修复 401 拦截 / 假点赞 / 退出登录落点（认证链路梳理）

**根因**：`api/client.ts` 的响应拦截器在 401/403 时 `return new Promise(() => {})`，
请求永不 settle。后果连锁：

- 调用方的 `catch` 永远不执行 → 乐观更新回滚不了 → 点赞看着点上、服务端没收到；
- 登录接口密码错也是 401，被当成"会话失效"去 clearAuth + 跳登录页，表单既不报错也不结束；
- 403（权限不足 / 隐私设置不允许查看）也被当成掉登录，会莫名清会话、和登录页来回弹；
- 拦截器里去 `router.replace("/auth")` 不看当前路由，在登录页时再 replace 会把输入中的
  登录表单整页重挂，形成「我的 ↔ 登录」循环。

**改动**：

1. `api/client.ts`
   - 401 **只在请求带 `Authorization` 时**视为会话失效（刷新 → 重试 → 仍失败才清会话跳登录）；
     匿名 401 原样 reject，交给调用方（登录表单能正常报错、访客点赞能回滚）。
   - 一律 `Promise.reject(error)`，并打 `authRedirected` 标记（`isAuthRedirectedError` 才有意义）。
   - 去掉 403 → 登录跳转（openapi 里 403 全是"权限不足"，不是失效）。
   - `redirectToLogin` 用 `lib/routeState.ts` 的 `isAuthRoute()` 判断，已在登录页就不 replace。
   - `useAuthStore.subscribe` 里 token 变非空时解除跳转锁。
2. `lib/routeState.ts`（新）：`setCurrentPathname/getCurrentPathname/isAuthRoute`，
   由 `app/_layout.tsx` 的 `usePathname()` effect 持续写入（expo-router 没有命令式读 pathname 的 API）。
3. `lib/authGate.ts`（新）：`ensureLoggedInForAction()` —— 未登录 toast「登录后才能进行该操作」+
   `router.push("/auth")`，返回 false；调用方拿到 false **必须先 return，不做乐观更新**。
   已接入：ArticleBottomBar（表态/收藏）、ReactionsStats、GestureImageViewer（点赞/收藏）、
   CommentItem（评论/回复赞）、CommentsTab、comment/[id]。
4. `ArticleBottomBar`：表态加 `reactionPendingRef` 串行锁；回滚基准改用本地 `userReaction/likeCount`
   （原来用 article props，连点时是旧值）；401 跳转时不弹「操作失败」。
5. 退出登录（`app/settings/index.tsx`）：`clearAuth` → `resetApiInstances` → `dismissAll` → `replace("/")`，
   不再去 `/auth`，也不再停在「我的」。
6. `app/auth/index.tsx`：登录/注册成功与返回都 `replace("/")`（首页），不再 `/(tabs)`。
7. `app/(tabs)/profile.tsx`：`isLoggedIn` 为假时 `refreshProfile` 直接返回；页面聚焦且未登录时
   `replace("/")` 兜底。
8. `locales/{zh,en}/common.json`：新增 `auth.loginActionRequired`；`locales/i18n.ts` 补 `export default i18n`。

**验证**：`npx tsc --noEmit`（过滤 `api/generated` 里既有的 `Null` 报错）无错；改动文件 eslint
仅剩既有告警（profile 的 refs/effect、ArticleBottomBar 的同步 effect）。未跑真机。

## 举报面板（useReport）请求失败改造：不再用原生 Alert

**原问题**：`handleSubmit` 先 `dismiss()` 再 `await onSubmit()`，失败时面板已经关掉，
调用方各自 `catch` 弹 `Alert.alert`（ShareModal / UserActionSheet）或 toast（CommentActionSheet）。
→ 用户看不到自己勾了什么、无法重试；原生弹窗样式不统一；没有提交中状态，能重复上报。

**改法**（`hooks/useReport.tsx`）：

- 顺序改成「先请求、后关面板」：成功 `dismiss()` + `toast(reportDialog.success)`；
  失败**不关面板**，`submitError` 渲染在按钮上方（`theme.danger`），选项/补充内容都保留，可直接重试。
- 错误文案优先取 `error.response.data.message`（NestJS 可能是字符串或数组），
  取不到才回退 `reportDialog.failed`——举报的 400/403 多是业务校验（举报自己、重复举报）。
- 未登录：`ensureLoggedInForAction()`（lib/authGate），先收面板再跳登录，不发注定 401 的请求。
- `isAuthRedirectedError` 时直接 dismiss（拦截器已清会话跳登录页），不叠加提示。
- 提交中：`submitting` + `submittingRef`，按钮转圈 + 文案「提交中…」+ 禁用，选项与输入框锁住，防重复上报。
- 三个调用点（ShareModal / UserActionSheet / CommentActionSheet）删掉 try/catch 与 Alert，只 `await`。

**新增文案**：`reportDialog.submitting/success/failed`（zh/en）。

**注意（后续若统一去 Alert）**：`GestureImageViewer` 用原生 `Modal`，root 层的 toast 会被 Modal 遮住，
那里的失败提示仍应保留 Alert 或改用 Modal 内部的提示；其余非 Modal 页面的 `Alert.alert(操作失败)`
可以安全换成 `toast.show`。

## 全站"操作失败"去掉原生 Alert（第二轮）

偏好：失败反馈一律用自研 UI（toast / 内联提示），不用 `Alert.alert`。

- `ArticleBottomBar`：表态失败 → `toast.show`（`isAuthRedirectedError` 时不提示）。
- `UserActionSheet`：拉黑失败 → `toast.show`。
- `ShareModal`：新增可选 `onError?: (message) => void`，内部 `notifyError` 默认走 `showToast`；
  不喜欢 / 拉黑 / 关注失败都走它。**大图查看器里必须传 `onError`**，否则 toast 被原生 Modal 盖住。
- `GestureImageViewer`（原生 Modal 内）：自建内联提示 `hint` + `hintOpacity`（Animated，2s 自动淡出），
  绝对定位在 `viewerBottomInset + 12`、`pointerEvents="none"`、`zIndex 30`；
  关注/点赞/收藏失败改调 `showHint`，并给 ShareModal 传 `onError={showHint}`。
  - `hintOpacity` 用 `useState(() => new Animated.Value(0))` 而不是 `useRef(...).current`，
    否则触发 `react-hooks/refs`（渲染期读 ref）。
- 仍然保留 `Alert.alert` 的只有 `components/media/ImageCropperSheet.tsx` 的**相机/相册权限**提示
  （阻断性提示，带标题+说明，不适合 toast）。

**经验**：`useConfirm` 的确认框是原生 `Modal`，但 `handleConfirm` 会**先 setVisible(false) 再 await onConfirm**，
所以确认之后的失败提示用 toast 不会被盖住；只有"宿主本身就是一个原生 Modal（大图查看器）"时才需要内联提示。

## 新增后端错误码文案命名空间 `response.error.*`

- 新增顶层 `response.error.duplicateReport`（zh/en）：举报重复时用。
- `useReport.tsx` 加了 `getErrorCode()` 读 `error.response.data.error`，
  提交失败的文案优先级：**`response.error.<code>` → `data.message` → `reportDialog.failed`**。
- 坑：NestJS 默认错误体的 `error` 是 HTTP 短语（"Conflict" / "Bad Request"），
  直接拿去查 i18n 查不到；用 `t(key, { defaultValue: "" })` 判空后再回退 message 即可，
  后面新增业务码只要往 `response.error` 里补 key，不用改逻辑。

## 大图查看器：点心点赞把 UI 收起来（事件穿透）

- 现象：在 `GestureImageViewer` 里点右栏「点赞 / 收藏」，动作生效的同时整个 chrome 收起。
- 根因：`onSingleTap` 是 `GestureViewer` 内部 `Gesture.Tap()` 在**原生层**按坐标命中判定的，
  不看 JS 树的 z 序；浮层控件（`rightRail` 叠在图片区上）被按下时，viewer 的 tap 也会激活。
  另外开了 `enableDoubleTapZoom`，单击回调要等双击判定失败，**比触摸起点晚几百毫秒**。
- 修法：`ViewerChrome` 根节点（`box-none` + absoluteFill）加 `onTouchStart` →
  `markChromeTouch()` 置一次性标记；`onSingleTap` 命中标记就吞掉并复位。
  - 不能用「触摸时间戳 + 固定时间窗」：双击判定的延迟不确定，窗口给小了会漏。
  - 标记必须配超时兜底（1200ms 自动过期）：某些平台不穿透时单击回调根本不来，
    标记不清会让**下一次正常点击白吃一次**。
  - 只有浮层子树会往上冒泡到根节点（点在空白处直接落到下面的 viewer），所以不需要逐个按钮加 `onPressIn`。

## 纯表情评论不显示（判空口径错了）

- 现象：只发了表情的评论在列表 / 详情页里整条看不见（楼层直接消失，只剩头像时间）。
- 根因：4 个组件各抄了一份 `hasRenderableContent`，口径是「剥掉 `<[^>]*>` 后 trim 是否为空」。
  表情评论的 content 是 `<span class="ql-emoji-embed" title="开心"><span><img …></span></span>`，
  剥完标签正好是空串 → 被当成空内容：`CommentReplyItem` / `CommentDetailReplyItem` 直接 `return null`，
  `CommentItem` / `CommentDetailMainComment` 跳过正文，有的还把 `content.trim()` 当第二道闸。
- 修法：新增 `lib/richText.ts` 统一口径 —— `hasRenderableHtml()` = 有可读文字 **或** 有内嵌媒体
  （`<img|video|audio|iframe>`），`hasRenderableContent(content, images)` 再并上附件图数组。
  4 个组件删掉本地副本改成引用；正文闸门用 `hasBody`（`hasRenderableHtml(content)`），
  列表项整条闸门用 `hasContent`（并上 images）。
- `components/profile/CommentCard.tsx`（我的评论）：原来「剥完标签为空 → 换成 [图片] 占位符」，
  纯表情被占位符顶掉；改成还剩表情就用原 HTML，真没东西才占位。
- 引用父评论 / 通知摘要这类只能显示文字的地方用新加的 `htmlToPreviewText()`
  （表情 span → `[名字]`，与私信列表 `formatLatestMessagePreview` 同一口径），
  没有 title 退 `[表情]`，其它 img 退 `[图片]`；新增 i18n `emojiContent`(zh/en)。
- 注意：`RenderHtml` 里 `img` 注册的是 `HTMLContentModel.mixed`，类名含 `ql-emoji` 的走
  固定尺寸行内渲染（`BODY_EMOJI_SIZE`），所以纯表情正文现在能正常出图。
