## 经验：patch-package 在 Windows 上重新生成补丁

`npx patch-package <pkg>` 会因 `node_modules/<pkg>/android/build/.transforms/...`
路径过长（git warning: Filename too long）直接以 status 128 失败，`--exclude`
无效。可行做法：先把两个包的 `android/build` 临时 `mv` 到项目外，
生成补丁后再移回：
`mv node_modules/<pkg>/android/build ../_tmp && npx patch-package <pkg> ... ; mv ../_tmp ...`
生成后用 `git apply --check --reverse -p1 --ignore-whitespace patches/<pkg>.patch`
校验补丁与当前 node_modules 一致。本次两个补丁均通过。

原生改动需要重新编译 native app 才生效（`expo run:android` / `run:ios`）。

## 追补：插入视频链接 sheet 弹在键盘底下（真机反馈）

上一轮把「键盘没弹出」理解成焦点问题，真机实际是 **sheet 弹出来了但被键盘压住、
完全没做键盘避让**。改动只在 `components/publish/InputSheet.tsx`。

**根因（读 `@gorhom/bottom-sheet` v5.2.14 源码确认）**：
- `src/hooks/useAnimatedKeyboard.ts` 只靠 `Keyboard.addListener('keyboardDidShow')`
  更新内部 `animatedKeyboardState`。键盘在点工具栏**之前**就已被正文编辑器唤起，
  sheet 挂载得晚，收不到那次 SHOWN → 状态一直是 `UNDETERMINED / height 0`，
  库认为没有键盘，面板按全屏底部定位，正好在键盘后面。
- `BottomSheet.tsx:1692-1708`：Android + `android_keyboardInputMode="adjustResize"`
  + `keyboardBehavior="interactive"` 时库把 `heightWithinContainer` 置 0 **并 return**，
  主动放弃位移，指望 window 缩小；而 `KeyboardProvider` 接管 WindowInsets 后
  并不保证 window 会 resize（尽管 AndroidManifest 里配了 `adjustResize`）。
- 所以「先收键盘再弹 sheet」虽能触发新事件，Android 上仍不位移，不是正解。

**修法**：不依赖 gorhom 的键盘事件，改用 `useKeyboardState`
（react-native-keyboard-controller 的全局 store，Provider 从根节点就一直有值，
与 sheet 挂载时机无关）算出 `keyboardInset`，传给 `BottomSheetModal` 的
`bottomInset` —— `BottomSheetHostingContainer` 会把它作为容器的 `bottom`，
把整个 sheet 抬到键盘上沿。`BottomSheetModalProps` 继承 `BottomSheetProps`
（只 Omit 掉 `containerHeight`/`onClose`），所以 `bottomInset` 合法。

配套：
- `keyboardBehavior` 从 `interactive` 改成 **`extend`**：单档位时
  `getEvaluatedPosition` 返回 `highestDetentPosition` = 当前位置，库不会再二次位移
  （interactive 在 iOS 会和 bottomInset 叠加把面板抬两次）。
- `snapPoints` 加下限 240：Android 键盘弹出会压缩 `windowHeight`，
  原来 `0.3 * windowHeight` 会矮到放不下输入框。
- 保留上一轮的 `requestKeyboardFocus` 多次重试 + 自动聚焦。

**同类隐患（本次未改）**：`InlinePostSheet` / `TopicPickerSheet` 同样从工具栏、
在键盘已显示时打开；InlinePostSheet 顶部有输入框且同样配了
`interactive + adjustResize`，如真机也出现可照此套 `bottomInset` 处理。
凡是「键盘先于 sheet 显示」的 bottom sheet 都会踩这个坑。

验证：eslint 零问题；tsc 仍只有 188 个 codegen `Null` 错误，改动文件零错误。
