## 文章编辑器审阅 → `docs/editor-review-plan.md`

应要求审阅富文本编辑器（工具栏 1495 行 / 输入框 121 / hook 237 / `lib/editorHtml` 309 /
原生补丁 30 文件 1875 行），产出评审 + 分三步的优化方案，未改业务代码。

审阅方法：读全部源码 + 用 esbuild 把 `lib/editorHtml.ts` 打到 node 跑真实 HTML 往返。

**三个 P0（都会发布出坏内容）**：
1. `toArticleHtml` 不区分块级/行内图：`<p>你好<img emoji/>世界</p>` 会被改成
   `<p>你好<div class="ql-image-wrapper">…</div>世界</p>`，div 被浏览器挤出 p，
   网页端表情变成整段居中大图。实测输出已记录。修法：两个捕获组分别处理，
   `inParagraph` 走 wrapper、`bare` 保持行内 `<img>`。
2. `insertDivider` 用 `savedSelectionRef.current.start`，而这个 ref 只在
   `rememberSelection()`（开 sheet / 表情面板）时更新，初始 `{start:0}` →
   **直接点「更多 → 分割线」会插到文首**。应改用实时的 `selectionRef.current`
   （`handleSelectEmoji` 就是这么写的）。
3. 分割线用 `setLink(…,"#")` + `setTimeout(200)` 摘链：窗口期内发布/切类型会留下
   `<a href="#">`，且这次修改不过 `onContentChanged`，撤销栈只记到中间态。

**P1**：`canUndo` 乐观置位导致「死按钮」（`pushHistory` 去重后不 `syncHistoryState`）；
撤销后光标丢失（`setValue` 不还选区）；`A⁺/A⁻` 字号基线是本地 state；
能力缺口（unlink / h5h6 / checkbox 列表有原生 API 无 UI）；插图不压缩；
图片无 alt；错误提示只有一句 `article.actionFailed`。

**P2/P3**：每键 `setBody` 触发整页重渲染；撤销栈存全量 HTML；
工具栏单文件；`getEditorContentWidth` 硬编码窗口宽-32 耦合 `PAGE_PADDING`；
render 期 `setPanelReserve`；色块 22pt / chip 32pt 触摸目标不足、读屏念 `rgb(...)`。

**结构性建议**：补丁块统一加 `// [picart]` 标记 + 锁版本 + 争取上游化；
`lib/editorHtml.ts` 是纯函数，最该补 vitest（这次 emoji bug 就是跑出来的，
看代码看不出来）；不要把编辑器换 WebView。

### 删掉回车自动跟底滚动

`app/publish` 里 `ScrollView.onContentSizeChange` 原本会在「内容变高 + 光标在末尾」时
`scrollTo({ animated: true })` 跟到底部，每按一次回车编辑区就平滑滑一下。
现在这个 handler 只记录 `lastContentHeightRef`，不再滚动。
**键盘弹起时的那次补滚动（350ms 后，`animated: true`）保留**——它不是回车触发的；
`caretAtEndRef` / `viewportHeightRef` 也因此保留。
若后续发现回车后光标跑到屏幕外，改成「仅当光标不可见时瞬间补一次」即可。
