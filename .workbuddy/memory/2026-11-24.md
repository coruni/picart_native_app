保留原则（写新代码时沿用）：

- 一句能说完的写一句，**优先留讲原因的那句**（含「否则 / 必须 / 不能 / 因为」），
  纯粹描述「这行在干嘛」的直接删。
- 装饰性分隔线（`// ─── Render ───`）一律不要。
- 被注释掉的旧代码、`eslint-disable` / `@ts-*` 指令块原样保留，别动。

codemod 踩过的坑（下次复用要记得）：

- 删 JSX 里的 `{/* ... */}` 必须连花括号一起删，否则留下裸的 `{}` 直接语法错误。
- 指令注释（`eslint-disable-next-line`）如果落在多行注释组里会被一起吃掉，
  表现为 lint 报错数变化；必须整组跳过。
- 多行注释里夹着被注释掉的代码（含 `<View` / `=>` / `style=`）不要压成一行。
- `Color.parseColor` 那类中英混排文本，join 时要补空格，且中文标点后面不能再补。
